# SAA-C03 — EC2 Fundamentals, Purchasing Options & Spot

> Thuộc **Domain 3: Design High-Performing Architectures** và **Domain 4: Design Cost-Optimized Architectures**: instance type, security group, user data và các mô hình mua EC2.
> Ký hiệu: `[+]` = bổ sung ngoài slide · `❓` = cần kiểm chứng · `⚠️` = lỗi thời.

---

## 1. TL;DR

- Tên instance `m5.2xlarge` = **family** (m) + **generation** (5) + **size** (2xlarge). Nhóm: General Purpose, Compute Optimized (C), Memory Optimized (R, X, z), Storage Optimized (I, D, H), Accelerated (P, G, Inf, Trn).
- **Security Group**: firewall cấp ENI, **stateful**, chỉ có rule **Allow**, tham chiếu được SG khác. Timeout → SG; "connection refused" → ứng dụng.
- **User data** chạy một lần lúc boot đầu tiên, quyền root.
- Mua EC2: **On-Demand** (ngắn, không gián đoạn), **Reserved Instances** & **Savings Plans** (cam kết 1–3 năm), **Spot** (rẻ nhất, có thể bị thu hồi), **Dedicated Host / Dedicated Instance**, **Capacity Reservation**.
- **Standard RI** bán được trên RI Marketplace; **Convertible RI** đổi được family/OS/tenancy nhưng không bán được.
- Savings Plans nay có **4 loại**: Compute, EC2 Instance, SageMaker AI, Database.
- **Spot** bị thu hồi chủ yếu khi EC2 **cần lại capacity**, báo trước 2 phút. Muốn dừng hẳn: **hủy Spot request trước**, rồi terminate instance.
- **Spot Fleet / EC2 Fleet** trộn Spot + On-Demand theo chiến lược phân bổ (price-capacity-optimized, lowest-price, diversified).

## 2. Core Concepts

### EC2 instance types
- **Là gì:** General Purpose (cân bằng, web server), Compute Optimized (batch, HPC, gaming, ML inference CPU), Memory Optimized (in-memory DB, cache, BI real-time), Storage Optimized (OLTP, NoSQL, data warehouse cần IOPS local cao).
- **Dùng khi nào:** chọn theo tài nguyên nghẽn: CPU → C; RAM → R/X; disk I/O local → I/D.
- **Vì sao quan trọng:** đề hay mô tả workload rồi hỏi family phù hợp.

### Security Groups
- **Là gì:** firewall ảo gắn ở ENI, kiểm soát port, giao thức, dải IP (IPv4/IPv6) hoặc SG nguồn.
- **Dùng khi nào:** mặc định chặn mọi inbound, cho phép mọi outbound; một instance có nhiều SG, một SG gắn nhiều instance.
- **Vì sao quan trọng:** gắn theo **Region + VPC**; tham chiếu SG thay IP giúp không phải sửa rule khi IP thay đổi.

### Port cần thuộc
- **Là gì:** 22 SSH/SFTP, 21 FTP, 80 HTTP, 443 HTTPS, 3389 RDP; DB: 3306 MySQL/MariaDB/Aurora MySQL, 5432 PostgreSQL, 1433 SQL Server, 1521 Oracle.
- **Dùng khi nào:** viết rule SG cho bastion, web tier, DB tier.
- **Vì sao quan trọng:** đề cho rule SG rồi hỏi kết nối nào chạy được.

### User data & cách kết nối
- **Là gì:** script chạy một lần khi instance khởi động lần đầu, quyền root; kết nối bằng SSH, PuTTY, **EC2 Instance Connect** (trên trình duyệt) hoặc Session Manager.
- **Dùng khi nào:** cài package, tải file cấu hình lúc launch.
- **Vì sao quan trọng:** không bao giờ chạy `aws configure` và lưu key trên EC2; dùng **IAM Role**.

### On-Demand & Reserved Instances
- **Là gì:** On-Demand trả theo giây (Linux/Windows), không cam kết; RI giảm giá khi cam kết 1 hoặc 3 năm, trả All/Partial/No Upfront, scope Regional hoặc Zonal.
- **Dùng khi nào:** On-Demand cho tải ngắn không đoán được; RI cho tải ổn định (database).
- **Vì sao quan trọng:** **Standard RI** giảm sâu nhất (tới ~72%) và bán được trên Marketplace; **Convertible RI** đổi được family, type, platform, scope, tenancy nhưng không mua/bán trên Marketplace. ❓ Slide ghi Convertible giảm 54% ở bảng nhưng 66% ở chỗ khác; mức thực tùy loại instance.

### Savings Plans
- **Là gì:** cam kết số $/giờ trong 1 hoặc 3 năm; phần vượt tính giá On-Demand.
- **Dùng khi nào:** **Compute SP** (tới ~66%, áp cho EC2 mọi family/Region, Fargate, Lambda); **EC2 Instance SP** (tới ~72%, khóa family + Region); **SageMaker AI SP**; **Database SP** (tới ~35%, Aurora, RDS, DynamoDB, ElastiCache...).
- **Vì sao quan trọng:** ⚠️ Lỗi thời: slide chỉ có Compute và EC2 Instance → nay thêm SageMaker AI và Database Savings Plans.

### Spot Instances
- **Là gì:** dùng capacity dư, giảm tới ~90%; nhận cảnh báo **2 phút** trước khi bị interrupt (stop, hibernate hoặc terminate).
- **Dùng khi nào:** batch, phân tích dữ liệu, xử lý ảnh, workload phân tán chịu lỗi; **không** dùng cho DB hay job quan trọng.
- **Vì sao quan trọng:** ⚠️ Lỗi thời: "bị thu hồi khi giá Spot vượt max price" → nay nguyên nhân chính là EC2 **cần lại capacity**; max price vẫn đặt được nhưng AWS khuyên không đặt.

### Spot request & Spot Fleet
- **Là gì:** request **one-time** hoặc **persistent**; persistent sẽ tự mở lại instance sau khi bị thu hồi. Spot Fleet = tập Spot (+ tùy chọn On-Demand) đạt target capacity. ⚠️ Lỗi thời: Spot Block (defined duration 1–6 giờ) → không còn cho khách mới từ 01/07/2021.
- **Dùng khi nào:** chiến lược: **price-capacity-optimized** (khuyến nghị), **capacity-optimized**, **lowest-price**, **diversified**.
- **Vì sao quan trọng:** hủy Spot request **không** terminate instance; phải hủy request trước, rồi terminate, nếu không persistent request tạo lại instance.

### Dedicated Hosts, Dedicated Instances, Capacity Reservations
- **Là gì:** **Dedicated Host** = cả server vật lý, thấy socket/core, cho **BYOL** theo socket/core và compliance; **Dedicated Instance** = phần cứng riêng nhưng không kiểm soát vị trí đặt; **On-Demand Capacity Reservation** = giữ chỗ trong một AZ, trả giá On-Demand dù không chạy.
- **Dùng khi nào:** BYOL / license gắn phần cứng → Dedicated Host; chỉ cần không chung phần cứng với khách khác → Dedicated Instance; cần chắc có capacity trong thời gian ngắn ở một AZ → Capacity Reservation.
- **Vì sao quan trọng:** Capacity Reservation không giảm giá; kết hợp với RI Regional hoặc Savings Plans để được giảm. ❓ Slide ghi Dedicated Instances thêm phí ~$2/giờ theo Region; cần xem lại trang giá hiện hành.

### `[+]` EC2 Instance Connect & Session Manager
- **Là gì:** Instance Connect đẩy SSH key tạm qua console; Session Manager mở shell qua SSM agent, **không cần mở port 22**, ghi log phiên.
- **Dùng khi nào:** "không mở inbound SSH, cần audit phiên" → Session Manager.
- **Vì sao quan trọng:** đáp án bảo mật thường thay bastion host bằng Session Manager.

## 3. Key Terms

| Term | Giải thích ngắn | Dấu hiệu trong đề |
|---|---|---|
| Security Group | Firewall stateful ở ENI, chỉ Allow | "instance-level firewall" |
| User data | Script chạy lúc boot đầu, quyền root | "bootstrap at launch" |
| On-Demand | Trả theo giây, không cam kết | "short-term, unpredictable, cannot be interrupted" |
| Standard RI | Giảm sâu, bán được trên Marketplace | "steady-state, 3 years" |
| Convertible RI | Đổi được family/OS/tenancy | "may change instance type" |
| Compute Savings Plans | Cam kết $/giờ, áp cho EC2/Fargate/Lambda | "flexible across Regions and services" |
| EC2 Instance Savings Plans | Cam kết $/giờ, khóa family + Region | "same family, any size/OS" |
| Spot Instance | Capacity dư, rẻ, có thể bị thu hồi | "fault-tolerant, flexible, cheapest" |
| Spot interruption notice | Cảnh báo 2 phút | "two-minute warning" |
| Spot Fleet | Tập Spot + On-Demand theo target | "mix instance types to reach capacity" |
| price-capacity-optimized | Chọn pool vừa rẻ vừa ít bị thu hồi | "lowest interruption and low cost" |
| Dedicated Host | Server vật lý riêng, thấy socket/core | "BYOL per-socket license" |
| Dedicated Instance | Phần cứng riêng, không chọn vị trí | "no shared hardware" |
| Capacity Reservation | Giữ capacity ở một AZ, không giảm giá | "guarantee capacity for a short event" |

## 4. Dễ nhầm & bẫy đề

### 4.1 Các cặp dễ lẫn

| Concept A | Concept B | Khác nhau ở đâu | Mẹo nhớ |
|---|---|---|---|
| Standard RI | Convertible RI | Standard giảm sâu hơn, bán được; Convertible đổi được thuộc tính, không bán được | Muốn đổi family → Convertible |
| Compute SP | EC2 Instance SP | Compute linh hoạt Region/service; EC2 Instance khóa family + Region, giảm sâu hơn | Có Lambda/Fargate → Compute SP |
| Dedicated Host | Dedicated Instance | Host: thấy socket/core, BYOL; Instance: chỉ cách ly phần cứng | License theo core → Host |
| Capacity Reservation | Reserved Instance | Reservation giữ chỗ, không giảm giá; RI giảm giá, chỉ giữ chỗ khi Zonal | "Guarantee capacity" → Reservation |
| Spot | On-Demand | Spot rẻ nhưng bị thu hồi; On-Demand không bị | "Cannot be interrupted" → không Spot |
| Hủy Spot request | Terminate Spot instance | Hủy request không terminate instance | Hủy request trước rồi terminate |
| Timeout | Connection refused | Timeout: SG/NACL chặn; refused: ứng dụng không chạy | Timeout → kiểm tra SG |

### 4.2 Từ khóa trong đề → chọn gì

| Từ khóa trong đề | Chọn | Ghi chú |
|---|---|---|
| "steady-state database for 3 years, lowest cost" | Standard RI / EC2 Instance SP | |
| "may change instance family later" | Convertible RI hoặc Compute SP | |
| "EC2 + Fargate + Lambda, commit spend" | Compute Savings Plans | |
| "batch job, can be interrupted, cheapest" | Spot Instances | |
| "critical job, cannot be interrupted, 2 months" | On-Demand | |
| "BYOL licensed per socket/core" | Dedicated Host | |
| "compliance: hardware not shared, no license need" | Dedicated Instance | |
| "guarantee capacity in one AZ for an event" | On-Demand Capacity Reservation | |
| "mix Spot and On-Demand to reach target capacity" | Spot Fleet / EC2 Fleet | |
| "terminate Spot for good" | Cancel request, rồi terminate | |
| "shell access without opening port 22" | SSM Session Manager | |

## 5. Câu hỏi tình huống

**Câu 1.** Một job xử lý ảnh chạy hằng đêm, chịu được gián đoạn và có checkpoint. Cần chi phí thấp nhất?
- A. On-Demand
- B. Spot Instances
- C. Standard RI 3 năm
- D. Dedicated Host

<details><summary>Đáp án</summary>

**B.** Spot rẻ nhất cho workload chịu lỗi.
- A sai: đắt hơn nhiều.
- C sai: job chỉ chạy ban đêm, cam kết 24/7 lãng phí.
- D sai: đắt nhất.
</details>

**Câu 2.** Công ty có license phần mềm tính theo số **socket vật lý** và muốn mang lên AWS. Chọn gì?
- A. Dedicated Instances
- B. Dedicated Hosts
- C. Spot Fleet
- D. Convertible RI

<details><summary>Đáp án</summary>

**B.** Dedicated Host cho thấy socket/core để tính license BYOL.
- A sai: Dedicated Instance không cho thấy cấu trúc phần cứng.
- C, D sai: là mô hình giá, không giải quyết license.
</details>

**Câu 3.** Admin hủy một persistent Spot request nhưng instance vẫn chạy. Sau đó terminate instance thì AWS lại tạo instance mới. Thứ tự đúng là gì?
- A. Terminate instance trước, rồi hủy request
- B. Hủy request trước, rồi terminate instance
- C. Chỉ cần stop instance
- D. Đổi sang one-time request rồi reboot

<details><summary>Đáp án</summary>

**B.** Hủy request trước để không có gì mở lại instance, sau đó terminate.
- A sai: request persistent còn hoạt động sẽ tạo lại instance (tình huống trong đề cho thấy thứ tự này sai).
- C sai: request vẫn còn.
- D sai: không đổi được loại request đang chạy.
</details>

**Câu 4.** (Chọn 2) Công ty muốn giảm chi phí cho EC2 chạy 24/7 trong 3 năm, nhưng có thể đổi instance family giữa chừng. Lựa chọn nào phù hợp?
- A. Convertible Reserved Instances
- B. Standard Reserved Instances
- C. Compute Savings Plans
- D. Spot Instances
- E. Dedicated Hosts

<details><summary>Đáp án</summary>

**A, C.** Cả hai cho phép đổi family.
- B sai: Standard không đổi được family.
- D sai: không phù hợp workload 24/7 cần ổn định.
- E sai: không phải mô hình giảm giá linh hoạt.
</details>

**Câu 5.** Web server trả về timeout khi truy cập port 80 từ Internet. Ứng dụng đang chạy bình thường. Nguyên nhân khả dĩ nhất?
- A. Ứng dụng crash
- B. Security Group chưa cho phép inbound port 80
- C. Thiếu IAM Role
- D. User data lỗi

<details><summary>Đáp án</summary>

**B.** Timeout thường do SG/NACL chặn.
- A sai: ứng dụng crash cho "connection refused".
- C sai: IAM không ảnh hưởng kết nối mạng.
- D sai: đề nói ứng dụng chạy bình thường.
</details>

**Câu 6.** Công ty cần chắc chắn có 50 instance `c6i.large` trong `us-east-1a` cho sự kiện 1 tuần, không muốn cam kết dài hạn. Chọn gì?
- A. Standard RI 1 năm
- B. On-Demand Capacity Reservation
- C. Spot Fleet
- D. Compute Savings Plans

<details><summary>Đáp án</summary>

**B.** Giữ capacity tại một AZ, hủy bất cứ lúc nào.
- A sai: cam kết 1 năm.
- C sai: Spot không đảm bảo capacity.
- D sai: Savings Plans không giữ capacity.
</details>

**Câu 7.** Ứng dụng dùng EC2, Fargate và Lambda; chi tiêu ổn định nhưng hay đổi Region và loại compute. Mô hình nào tiết kiệm nhất?
- A. EC2 Instance Savings Plans
- B. Compute Savings Plans
- C. Standard RI
- D. Database Savings Plans

<details><summary>Đáp án</summary>

**B.** Áp cho EC2 mọi family/Region, Fargate và Lambda.
- A sai: khóa family + Region, không áp cho Fargate/Lambda.
- C sai: chỉ EC2, không linh hoạt.
- D sai: dành cho dịch vụ database.
</details>

**Câu 8.** Spot Fleet cần vừa rẻ vừa ít bị gián đoạn nhất. Chiến lược phân bổ nào?
- A. lowest-price
- B. diversified
- C. price-capacity-optimized
- D. On-Demand only

<details><summary>Đáp án</summary>

**C.** Chọn pool có capacity tốt và giá thấp; là chiến lược AWS khuyến nghị.
- A sai: rẻ nhất nhưng dễ bị thu hồi.
- B sai: rải đều pool, không tối ưu cả hai.
- D sai: không dùng Spot.
</details>
