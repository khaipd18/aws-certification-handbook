# CLF-C02 — Amazon EC2

> Thuộc **Domain 3: Cloud Technology and Services (34%)** (compute) và **Domain 4** (purchasing options). EC2 là nền tảng để hiểu các dịch vụ còn lại.
> Ký hiệu: `[+]` = bổ sung ngoài slide · `❓` = cần kiểm chứng · `⚠️` = lỗi thời.

---

## 1. TL;DR

- **EC2 (Elastic Compute Cloud)** = thuê **máy ảo** trên AWS, là ví dụ điển hình của **IaaS**.
- Cấu hình một instance: **AMI (OS) + instance type (CPU/RAM) + storage + security group + user data**.
- **EC2 User Data** = script bootstrap chạy **một lần** khi instance khởi động lần đầu, với quyền **root**.
- Instance type đọc như `m5.2xlarge`: **class** (m) + **generation** (5) + **size** (2xlarge). Các nhóm: General Purpose, Compute, Memory, Storage Optimized, Accelerated Computing, HPC Optimized.
- **Security Group** = firewall cấp instance, **chỉ có Allow rule**, mặc định chặn mọi inbound và cho phép mọi outbound.
- Port cần thuộc: **22** SSH/SFTP, **21** FTP, **80** HTTP, **443** HTTPS, **3389** RDP.
- Purchasing options: **On-Demand, Reserved Instances, Savings Plans, Spot, Dedicated Hosts, Dedicated Instances, Capacity Reservations**. Spot rẻ nhất (tới 90%), Dedicated Host đắt nhất.
- Shared Responsibility: AWS lo phần cứng và cách ly host; **khách hàng lo OS patch, security group, phần mềm, IAM role, dữ liệu**.

## 2. Core Concepts

### Amazon EC2 là gì
- **Là gì:** dịch vụ thuê máy ảo; hệ sinh thái gồm EC2 (VM), EBS (ổ đĩa mạng), ELB (cân bằng tải), ASG (tự scale).
- **Dùng khi nào:** cần toàn quyền kiểm soát OS và phần mềm.
- **Vì sao quan trọng:** hiểu EC2 là hiểu cách cloud vận hành; nhiều dịch vụ managed chạy trên EC2 bên dưới.

### Tùy chọn cấu hình
- **Là gì:** OS (Linux, Windows, macOS), số vCPU, RAM, storage (EBS/EFS gắn qua mạng hoặc Instance Store gắn phần cứng), network card và public IP, security group, user data.
- **Dùng khi nào:** chọn đúng kích thước theo workload (rightsizing, chương 19).
- **Vì sao quan trọng:** đề có thể hỏi "thành phần nào cấu hình khi launch EC2".

### EC2 User Data
- **Là gì:** script chạy **một lần** lúc instance khởi động lần đầu, với quyền root.
- **Dùng khi nào:** cài update, cài phần mềm, tải file chung khi khởi động.
- **Vì sao quan trọng:** khác với AMI (đóng gói sẵn phần mềm). User data = cấu hình **lúc boot**.

### Instance types & naming
- **Là gì:** `m5.2xlarge` = class `m` + generation `5` + size `2xlarge`.
- **Dùng khi nào:** General Purpose (web server, code repo, cân bằng CPU/RAM/mạng; vd: `t2.micro` dùng trong khóa học); Accelerated Computing (GPU) cho ML, đồ họa.
- **Vì sao quan trọng:** đề cho workload và hỏi nhóm instance phù hợp.

### Compute / Memory / Storage Optimized
- **Là gì:** **Compute** (C): batch, media transcoding, web server hiệu năng cao, HPC, ML, game server; **Memory** (R/X): xử lý dataset lớn **trong RAM**, in-memory DB, cache, BI real-time.
- **Dùng khi nào:** **Storage Optimized** (I/D/H): đọc/ghi tuần tự cao trên **local storage**: OLTP tần suất cao, NoSQL, cache cho Redis, data warehouse, distributed file system.
- **Vì sao quan trọng:** mẹo: "in-memory" → Memory; "CPU-intensive" → Compute; "high sequential I/O on local disk" → Storage.

### Security Groups
- **Là gì:** firewall gắn **bên ngoài** instance, kiểm soát port, dải IP (IPv4/IPv6), inbound và outbound; rule tham chiếu được IP hoặc security group khác.
- **Dùng khi nào:** gắn được vào nhiều instance; gắn với một Region + VPC; nên tách một SG riêng cho SSH.
- **Vì sao quan trọng:** **timeout** → lỗi security group; **connection refused** → lỗi ứng dụng hoặc app chưa chạy.

### Security Group defaults
- **Là gì:** mặc định **chặn mọi inbound**, **cho phép mọi outbound**; chỉ có **Allow** rule (không có Deny).
- **Dùng khi nào:** muốn chặn một IP cụ thể thì cần NACL (chương 13), không dùng được SG.
- **Vì sao quan trọng:** SG là **stateful**: traffic trả về của kết nối đã cho phép tự động được đi qua.

### Classic ports
- **Là gì:** 22 = SSH (Linux) và SFTP; 21 = FTP; 80 = HTTP; 443 = HTTPS; 3389 = RDP (Windows).
- **Dùng khi nào:** mở port tương ứng trong security group.
- **Vì sao quan trọng:** đề hỏi "port nào để quản trị Windows từ xa" → 3389.

### Kết nối vào instance: SSH, PuTTY, EC2 Instance Connect
- **Là gì:** SSH (Mac/Linux/Windows 10+), PuTTY (Windows cũ), **EC2 Instance Connect** (trên trình duyệt, AWS đẩy SSH public key tạm thời vào instance, tồn tại 60 giây).
- ⚠️ Lỗi thời: "Instance Connect chỉ chạy sẵn với Amazon Linux 2" → nay có sẵn trên một số AMI (Amazon Linux 2, Amazon Linux 2023...) và cài được trên AMI hỗ trợ khác; vẫn cần **port 22** mở.
- **Vì sao quan trọng:** Instance Connect dùng IAM để kiểm soát và ghi log vào CloudTrail, không cần quản lý key file.

### On-Demand Instances
- **Là gì:** trả theo mức dùng; Linux/Windows tính **theo giây sau phút đầu tiên**, OS khác tính theo giờ.
- **Dùng khi nào:** workload ngắn hạn, không bị gián đoạn, không dự đoán được.
- **Vì sao quan trọng:** giá cao nhất (trừ Dedicated) nhưng không trả trước, không cam kết.

### Reserved Instances (RI)
- **Là gì:** cam kết **1 hoặc 3 năm** với thuộc tính cụ thể (instance type, Region, tenancy, OS); giảm **tới 72%**; trả No/Partial/All Upfront (trả trước càng nhiều càng rẻ).
- **Dùng khi nào:** workload **ổn định, chạy liên tục** (vd: database). Scope Regional hoặc Zonal (Zonal giữ capacity trong một AZ).
- **Vì sao quan trọng:** **Convertible RI** đổi được instance type, family, OS, scope, tenancy, giảm tới khoảng 66%; RI mua bán được trên **RI Marketplace**.

### EC2 Savings Plans
- **Là gì:** cam kết **số tiền mỗi giờ** (vd: $10/giờ) trong 1 hoặc 3 năm; EC2 Instance Savings Plans giảm **tới 72%**; dùng vượt mức tính giá On-Demand.
- **Dùng khi nào:** khóa vào một **instance family + Region** (vd: M5 ở us-east-1), linh hoạt size, OS, tenancy.
- **Vì sao quan trọng:** Compute Savings Plans (linh hoạt hơn, áp dụng cả Fargate và Lambda) ở chương 16.

### Spot Instances
- **Là gì:** dùng capacity EC2 dư, giảm **tới 90%**; có thể bị **thu hồi** bất cứ lúc nào. Rẻ nhất trong các lựa chọn.
- ⚠️ Lỗi thời: "mất instance khi max price thấp hơn spot price" (mô hình đấu giá) → nay lý do chính là **EC2 cần lấy lại capacity**; nếu bạn đặt max price thì còn bị thu hồi thường xuyên hơn.
- **Dùng khi nào:** workload **chịu được lỗi**, thời gian linh hoạt: batch, phân tích dữ liệu, xử lý ảnh, distributed; **không** dùng cho DB hay job quan trọng.

### Dedicated Hosts
- **Là gì:** **cả một server vật lý** dành riêng cho bạn, kiểm soát được việc đặt instance trên host; mua On-Demand hoặc Reserved 1/3 năm.
- **Dùng khi nào:** license gắn với server (per-socket, per-core, per-VM, **BYOL**) hoặc yêu cầu compliance chặt.
- **Vì sao quan trọng:** **đắt nhất**. Từ khóa "server-bound software license" → Dedicated Host.

### Dedicated Instances
- **Là gì:** instance chạy trên phần cứng dành riêng cho account bạn, nhưng **không kiểm soát** việc đặt instance (stop/start có thể sang host khác).
- **Dùng khi nào:** cần không chia sẻ phần cứng với khách hàng khác nhưng không cần quản lý license theo socket/core.
- **Vì sao quan trọng:** khác Dedicated Host ở chỗ không có quyền nhìn và kiểm soát server vật lý.

### Capacity Reservations
- **Là gì:** giữ capacity On-Demand trong **một AZ cụ thể** bao lâu tùy ý; **không cam kết thời gian**, **không giảm giá**.
- **Dùng khi nào:** workload ngắn hạn, không được gián đoạn, bắt buộc ở một AZ; kết hợp Regional RI hoặc Savings Plans để có giảm giá.
- **Vì sao quan trọng:** bị tính giá On-Demand **dù có chạy instance hay không**.

### Shared Responsibility cho EC2
- **Là gì:** AWS: hạ tầng, bảo mật mạng toàn cầu, **cách ly trên host vật lý**, thay phần cứng hỏng, compliance validation.
- **Dùng khi nào:** khách hàng: **security group rules**, **OS patches & updates**, phần mềm cài trên instance, IAM role gán cho EC2, bảo mật dữ liệu trên instance.
- **Vì sao quan trọng:** "ai vá guest OS của EC2" → **khách hàng** (khác RDS, AWS vá OS).

### `[+]` EC2 Instance Connect Endpoint
- **Là gì:** cho phép kết nối SSH/RDP vào instance **không có public IP** trong private subnet, không cần bastion host.
- **Dùng khi nào:** instance ở private subnet và không muốn mở Internet.
- **Vì sao quan trọng:** cùng nhóm với SSM Session Manager (chương 9) cho câu hỏi "truy cập instance an toàn không cần port 22 public".

## 3. Key Terms

| Term | Giải thích ngắn | Dấu hiệu trong đề |
|---|---|---|
| EC2 | Máy ảo trên AWS (IaaS) | "virtual server", "full OS control" |
| AMI | Image gồm OS và phần mềm để launch instance | "template for instances" |
| Instance type | Tổ hợp CPU/RAM/network (`m5.2xlarge`) | "instance family", "size" |
| EC2 User Data | Script chạy một lần lúc boot đầu tiên, quyền root | "bootstrap", "install software at launch" |
| Security Group | Firewall stateful cấp instance, chỉ Allow | "allow inbound port 443" |
| SSH / RDP | Truy cập Linux (22) / Windows (3389) | "remote administration" |
| EC2 Instance Connect | SSH qua trình duyệt, key tạm thời | "connect without managing key file" |
| On-Demand | Trả theo giây/giờ, không cam kết | "short-term, unpredictable, no interruption" |
| Reserved Instance | Cam kết 1/3 năm, giảm tới 72% | "steady-state", "database running 24/7" |
| Convertible RI | RI đổi được family/OS/tenancy | "flexibility to change instance type" |
| RI Marketplace | Nơi mua bán RI chưa dùng hết | "sell unused reservations" |
| EC2 Instance Savings Plan | Cam kết $/giờ cho một family trong một Region | "commit to hourly spend" |
| Spot Instance | Capacity dư, giảm tới 90%, có thể bị thu hồi | "fault-tolerant", "flexible start/end", "cheapest" |
| Dedicated Host | Server vật lý riêng, thấy socket/core | "BYOL", "server-bound licenses" |
| Dedicated Instance | Phần cứng riêng cho account, không kiểm soát placement | "not shared with other customers" |
| Capacity Reservation | Giữ capacity ở một AZ, không giảm giá | "guarantee capacity in specific AZ" |
| Timeout vs connection refused | Lỗi SG vs lỗi ứng dụng | "cannot reach instance" |

## 4. Dễ nhầm & bẫy đề

### 4.1 Các cặp dễ lẫn

| Concept A | Concept B | Khác nhau ở đâu | Mẹo nhớ |
|---|---|---|---|
| Reserved Instance | Savings Plan | RI cam kết **thuộc tính instance**; SP cam kết **$/giờ** | "Commit to spend" → Savings Plan |
| Standard RI | Convertible RI | Standard rẻ hơn nhưng không đổi family; Convertible đổi được, giảm ít hơn | "Might change instance type" → Convertible |
| Spot | On-Demand | Spot rẻ tới 90% nhưng bị thu hồi; On-Demand không bị gián đoạn | Job quan trọng/DB → **không** Spot |
| Dedicated Host | Dedicated Instance | Host: thấy và kiểm soát server, phục vụ BYOL; Instance: chỉ phần cứng riêng | "per-socket/per-core license" → Host |
| Capacity Reservation | Reserved Instance | CR giữ capacity, **không giảm giá**, không cam kết; RI giảm giá, cam kết 1/3 năm | "Guarantee capacity, no commitment" → CR |
| Zonal RI | Regional RI | Zonal giữ capacity trong AZ; Regional linh hoạt AZ, không giữ capacity | |
| User Data | AMI | User Data chạy script lúc boot; AMI đóng gói sẵn phần mềm | Boot nhanh hơn → AMI |
| Security Group | NACL | SG: instance-level, stateful, chỉ Allow; NACL: subnet-level, stateless, Allow + Deny | Chặn một IP → NACL |
| Timeout | Connection refused | Timeout = SG chặn; refused = app lỗi | |
| Compute Optimized | Memory Optimized | CPU-intensive vs dataset lớn trong RAM | "in-memory DB" → Memory |
| Memory Optimized | Storage Optimized | RAM vs I/O tuần tự trên local disk | "high sequential read/write local" → Storage |

### 4.2 Từ khóa trong đề → chọn gì

| Từ khóa trong đề | Chọn | Ghi chú |
|---|---|---|
| "batch job, can be interrupted, lowest cost" | Spot | |
| "database running 24/7 for 3 years" | Reserved Instance (hoặc Savings Plan) | |
| "unpredictable, short-term, cannot be interrupted" | On-Demand | |
| "existing per-core software license, compliance" | Dedicated Host | Đắt nhất |
| "no other customers on the hardware" | Dedicated Instance | |
| "must have capacity in us-east-1a during event" | On-Demand Capacity Reservation | |
| "install software automatically at first boot" | EC2 User Data | |
| "machine learning, video transcoding, HPC, gaming server" | Compute Optimized (hoặc Accelerated cho GPU) | |
| "in-memory database, real-time big data" | Memory Optimized | |
| "OLTP, NoSQL, data warehouse on local storage" | Storage Optimized | |
| "app times out on port 80" | Kiểm tra Security Group | |
| "log in to Windows instance" | RDP 3389 | |
| "who patches EC2 guest OS" | Customer | |

## 5. Câu hỏi tình huống

**Câu 1.** Công ty chạy một database trên EC2 24/7 và chắc chắn dùng ít nhất 3 năm. Lựa chọn tiết kiệm nhất mà không bị gián đoạn?
- A. Spot Instances
- B. On-Demand Instances
- C. Reserved Instances 3 năm, All Upfront
- D. Capacity Reservations

<details><summary>Đáp án</summary>

**C.** Workload ổn định dài hạn → RI 3 năm trả trước toàn bộ cho mức giảm lớn nhất.
- A sai: Spot có thể bị thu hồi, không hợp với database.
- B sai: đắt hơn cho workload chạy liên tục.
- D sai: Capacity Reservation không giảm giá.
</details>

**Câu 2.** Một job xử lý ảnh hằng đêm có thể chạy lại nếu bị dừng, thời điểm bắt đầu linh hoạt. Lựa chọn rẻ nhất?
- A. Dedicated Hosts
- B. Spot Instances
- C. On-Demand Instances
- D. Reserved Instances

<details><summary>Đáp án</summary>

**B.** Workload chịu được gián đoạn, linh hoạt thời gian → Spot (giảm tới 90%).
- A sai: đắt nhất.
- C sai: đắt hơn Spot nhiều.
- D sai: cần cam kết dài hạn, không hợp job thất thường.
</details>

**Câu 3.** Công ty muốn dùng license phần mềm hiện có tính theo số socket vật lý. Lựa chọn nào phù hợp?
- A. Dedicated Instances
- B. Dedicated Hosts
- C. Spot Instances
- D. Savings Plans

<details><summary>Đáp án</summary>

**B.** Dedicated Host cho thấy và kiểm soát socket/core của server vật lý, phục vụ BYOL.
- A sai: không cho quyền kiểm soát server vật lý.
- C, D sai: không liên quan đến license theo phần cứng.
</details>

**Câu 4.** Người dùng truy cập website trên EC2 và bị **timeout**. Nguyên nhân khả dĩ nhất?
- A. Ứng dụng web bị crash
- B. Security group chưa mở port cần thiết
- C. Instance hết RAM
- D. Hệ điều hành chưa được vá

<details><summary>Đáp án</summary>

**B.** Timeout thường do security group chặn traffic.
- A sai: app lỗi thường trả "connection refused".
- C, D sai: không phải nguyên nhân điển hình của timeout.
</details>

**Câu 5.** (Chọn 2) Theo Shared Responsibility Model, khách hàng chịu trách nhiệm gì khi dùng EC2?
- A. Vá hệ điều hành của instance
- B. Thay ổ cứng hỏng trong data center
- C. Cấu hình security group rules
- D. Cách ly instance trên host vật lý
- E. Bảo mật mạng toàn cầu của AWS

<details><summary>Đáp án</summary>

**A, C.**
- B, D, E sai: là trách nhiệm của AWS.
</details>

**Câu 6.** Admin muốn mỗi EC2 mới tự cài web server và tải file cấu hình khi khởi động lần đầu. Dùng gì?
- A. EC2 User Data
- B. Security Group
- C. IAM Access Advisor
- D. Elastic IP

<details><summary>Đáp án</summary>

**A.** User data là script bootstrap chạy một lần lúc boot đầu tiên.
- B sai: firewall.
- C sai: công cụ audit quyền.
- D sai: IP public cố định.
</details>

**Câu 7.** Ứng dụng phân tích cần xử lý dataset rất lớn **trong bộ nhớ** để ra kết quả real-time. Nhóm instance nào phù hợp?
- A. Compute Optimized
- B. Memory Optimized
- C. Storage Optimized
- D. General Purpose

<details><summary>Đáp án</summary>

**B.** Memory Optimized dành cho workload xử lý dữ liệu lớn trong RAM.
- A sai: tối ưu CPU.
- C sai: tối ưu I/O trên local disk.
- D sai: cân bằng, không chuyên cho RAM.
</details>

**Câu 8.** (Chọn 2) Phát biểu nào về Security Group là **đúng**?
- A. Mặc định cho phép mọi inbound traffic
- B. Chỉ có rule Allow, không có rule Deny
- C. Mặc định cho phép mọi outbound traffic
- D. Gắn ở cấp subnet
- E. Là stateless

<details><summary>Đáp án</summary>

**B, C.**
- A sai: mặc định chặn mọi inbound.
- D sai: gắn ở cấp instance (ENI); NACL mới gắn ở subnet.
- E sai: security group là stateful.
</details>
